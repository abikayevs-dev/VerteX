# VerteX BLE — готовый скетч на основе присланной прошивки

Откройте `VerteX_BLE/VerteX_BLE.ino`. Рядом обязательно должен лежать `VertexBLEBridge.h`. В Arduino IDE это один проект с двумя вкладками. Дополнительные библиотеки IMU не нужны; BLE и Wire входят в Arduino-ESP32 3.x.

## Подключения сохранены

| Узел | Подключение |
|---|---|
| SDA | GPIO16 |
| SCL | GPIO21 |
| TCA9548A | 0x70; каналы 0/1/2 |
| MPU | 0x68 на каждом канале |
| Верхняя пара моторов | GPIO25 через существующий MOSFET |
| Средняя пара моторов | GPIO26 через существующий MOSFET |
| Нижняя пара моторов | GPIO27 через существующий MOSFET |

Алгоритм исходника сохранён: каждый датчик сравнивается со своей калибровкой; фильтр 0,12 с; защита от движения и ошибок I²C; порог 5°, возврат 3°, задержка 700 мс; вибрация 500 мс / пауза 1500 мс по умолчанию. Пороги меняются независимо; возврат = свой порог минус 2° (минимум 1°).

## Arduino IDE

1. Распакуйте архив. Откройте .ino из папки `VerteX_BLE`, не из ZIP.
2. Выберите свою плату ESP32 WROOM-32 / ESP32 Dev Module и её COM-порт. Используйте установленную ветку **esp32 by Espressif Systems 3.x**, например вашу 3.3.x. Этот скетч не нацелен на изменённый BLE API ветки 4.x.
3. Нажмите «Проверить», затем «Загрузить». Если компилятор сообщает о нехватке места, выберите Partition Scheme → Huge APP для вашей платы 4 MB и повторите. Это разметка без OTA; скетч OTA не использует.
4. Serial Monitor: **115200**, конец строки Newline. Должна появиться строка `BLE READY: VerteX-001`.
5. Исходный запуск сохранён: 8 секунд на принятие нейтральной позы, затем примерно 3 секунды неподвижных измерений. При успехе — `CAL OK`, мониторинг запускается автоматически. При отказе калибровки отправьте CAL; при ошибке датчиков — REINIT после проверки соединений.

## Сайт

Опубликуйте обновлённый сайт из основного архива. Старый сайт использует другой формат телеметрии и не подходит.

1. Откройте HTTPS-сайт в Chrome на Windows или Android. Включите Bluetooth на компьютере/телефоне.
2. В дашборде нажмите **Подключить BLE** → выберите **VerteX-001**. Подключение выбирается прямо в браузере; отдельное сопряжение через настройки Windows обычно не требуется.
3. Сайт прочитает фактические настройки с платы. Если плата уже завершила стартовую калибровку, поступят реальные показания.
4. Для новой калибровки нажмите **Калибровать**: 5 секунд на подготовку + примерно 3 секунды неподвижно. Сайт покажет процесс. После успешной калибровки мониторинг запускается автоматически, как в исходнике.
5. Измените пороги, задержку или ритм вибрации → **Применить на устройстве**. Подпись «Подтверждено ESP32» обновится после ответа платы.
6. **Остановить устройство** выключает все моторы и отменяет калибровку/тест. После STOP можно запустить мониторинг снова, если калибровка остаётся действительной.
7. Отключение BLE останавливает мониторинг, калибровку и моторы. При повторном подключении остановленный сеанс сам не запускается; нажмите запуск или калибровку.

Диапазоны соответствуют исходнику: пороги **3–45°**, задержка **0–30000 мс**; добавленные ON **100–1000 мс**, OFF **500–10000 мс**. Настройки хранятся до перезагрузки платы. При движении/недостоверных измерениях сайт не засчитывает интервал как правильную осанку.

Все старые Serial-команды сохранены. Добавлены `ON:500` и `OFF:1500`. После изменения параметров через Serial нажмите на сайте «Прочитать настройки».

## BLE v1

Service `91bad492-b950-4226-aa2b-4ede9fa42f59`
Telemetry READ/NOTIFY `cba1d466-344c-4be3-ab3f-189f80dd7518`
Control READ/WRITE/NOTIFY `cba1d467-344c-4be3-ab3f-189f80dd7518`

Каждый пакет 20 байт, целые little endian; подходит стандартный MTU. Период телеметрии 200 мс. Время сеанса берётся из millis(), не из числа пакетов.

Команда: byte0=1, byte1=операция GET 0 / SETTINGS 1 / START 2 / STOP 3 / CAL 4; bytes2–3=id команды. Настройки: uint16 по смещениям 6/8/10 — пороги ×10; 12 — задержка; 14 — ON; 16 — OFF; byte18 — feedback 0/1. Время в мс.

Ответ Control: byte0=1, byte1=2, bytes2–3=id, byte4=статус 0 успех/1 отказ; фактические настройки по тем же смещениям. Для CAL успех означает **запуск**, а не завершение. Результат приходит в телеметрии.

Телеметрия: byte0=1, byte1=1, bytes2–3=счётчик; byte4 flags: bit0 monitoring, bit1 calibrated, bit2 fault, bit3 calibrating, bit4 testing; byte5=маска подтверждённых отклонений; uint16 6/8/10=углы ×10; byte12=маска моторов; byte13=маска достоверных измерений; uint32 14=millis(). Маски: bit0 верх, bit1 середина, bit2 низ. Остальные байты нулевые.

Команды ставятся в очередь BLE-задачей и выполняются только в основном loop — I²C и моторы не изменяются конкурентно из BLE callback.

## Проверки и ограничения

Проведены: C++ сборка с имитаторами Arduino/BLE и тесты реальной логики исходника (независимость зон, задержка, ритм, гистерезис, границы настроек, калибровка, отключение и Serial); JavaScript-тесты протокола, ACK, времени, дублей, Groq и входа. Имитаторы не заменяют компиляцию с пакетом ESP32.

Полная сборка Arduino-ESP32 и физическое испытание не выполнены: в среде не удалось загрузить пакет плат. Первое подключение и фактическую вибрацию нужно проверить на вашем устройстве. При ошибке сборки нужен полный текст ошибки.

Это BLE-прототип без pairing/bonding/PIN. Supabase-вход не является защитой Bluetooth-канала; не позиционируйте эту версию как защищённую систему для публичного использования.
