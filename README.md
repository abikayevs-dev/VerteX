# VerteX — запуск через GitHub и Netlify

В комплекте: сайт с фотографиями нового MVP, дашборд BLE/демо, Groq с выбором модели, Supabase Auth (регистрация, подтверждение почты, вход, выход, восстановление пароля).

## 1. Supabase

1. Откройте https://supabase.com/dashboard и создайте проект или выберите свой.
2. Скопируйте Project URL и публичный Publishable key (либо legacy anon key) из настроек подключения/API.
3. В `config.js` заполните `supabaseUrl` и `supabasePublishableKey`. Эти параметры публичные. Никогда не используйте secret / service_role key.
4. В Authentication включите Email/Password, разрешите новые регистрации и включите Confirm email. Установите минимум 10 символов для пароля.
5. После публикации укажите точный адрес сайта, например `https://YOUR-SITE.netlify.app/`, в Authentication → URL Configuration → Site URL и Redirect URLs. При смене домена обновите оба поля.
6. Для регистрации внешних пользователей настройте Custom SMTP (например, Resend с подтверждённым доменом). Встроенная отправка Supabase ограничена и не предназначена для публичной регистрации произвольных адресов.

SQL не требуется: учётные записи создаёт Supabase Auth. История сеансов и API-ключи в базу не записываются. Клиентская проверка входа перед ИИ — удобство интерфейса, не серверная защита платного сервиса; каждый пользователь выполняет запросы со своим ключом.

## 2. GitHub → Netlify

1. Распакуйте архив. Загрузите **содержимое** папки `vertex` в корень репозитория GitHub: `index.html`, `app.js`, `ble-protocol.js`, `styles.css`, `config.js`, `netlify.toml`, папки `assets` и `firmware`, README и `.gitignore`.
2. В Netlify создайте проект через импорт существующего репозитория и выберите GitHub.
3. Выберите репозиторий. Base directory оставьте пустым, Build command — пустым, Publish directory — `.`. Если в репозитории лежит сама папка vertex, используйте Base directory `vertex`.
4. Опубликуйте проект. `netlify.toml` уже содержит настройки статической публикации.
5. Добавьте полученный домен в Supabase (шаг 1.5). Изменения config.js отправьте коммитом в GitHub — Netlify выполнит новое развёртывание.

Не открывайте index.html через file:// для проверки регистрации. Используйте опубликованный HTTPS-сайт либо локальный HTTP-сервер. Например, из папки проекта: `python -m http.server 8000`. Для локальной проверки добавьте `http://localhost:8000/` в разрешённые Redirect URLs Supabase.

## 3. Groq

1. Получите личный ключ: https://console.groq.com/keys . В GitHub его загружать не нужно.
2. На сайте войдите в аккаунт, откройте дашборд, вставьте ключ и нажмите «Подключить и загрузить модели».
3. Выберите модель из списка. Доступность моделей зависит от тарифа и лимитов Groq. Аудиомодели и классификаторы исключены из списка; новые специализированные модели могут не поддерживать формат отчёта.
4. Запустите демо, накопите показатели, при необходимости остановите его и нажмите «Создать ИИ-анализ».
5. Ключ находится только в памяти страницы, исчезает при перезагрузке/выходе. Кнопка «Удалить ключ» также его очищает. Сессия Supabase сохраняется SDK в браузере до выхода.

ИИ получает снимок текущего сеанса с меткой источника: демо или ESP32 BLE. Реальные показания появятся после загрузки комплектной прошивки VerteX_BLE и подключения платы. Смена источника начинает новый сеанс и не смешивает реальные данные с демо. При запросе показатели уходят напрямую в Groq. Отчёт не является медицинским заключением.

## 4. Проверка после настройки

- Зарегистрировать новый email → открыть письмо → подтвердить аккаунт → войти.
- Выйти и войти снова; проверить сохранение входа после перезагрузки.
- «Забыли пароль?» → письмо → новый пароль → повторный вход.
- Ввести ключ → загрузить модели → выбрать модель → демосеанс → анализ.
- Проверить неверный ключ, отсутствие средств/лимит, отключённый интернет.

Фото рашгарда и модуля лежат в assets и публикуются вместе с сайтом. Это студийно обработанные изображения реального прототипа. Шрифты и SDK загружаются с CDN; для них нужен интернет. Новый блок аккаунта и подключения ИИ на русском; существующие переводы сайта сохранены.

Без ваших настроек Supabase и личного ключа нельзя проверить доставку писем и настоящий ответ модели. Проект не был опубликован в ваших аккаунтах автоматически.

Документация:
- https://supabase.com/docs/guides/auth/passwords
- https://supabase.com/docs/guides/auth/auth-smtp
- https://console.groq.com/docs/models
- https://docs.netlify.com/start/quickstarts/deploy-from-repository/

Проверка разработки: синтаксис JavaScript и автоматические проверки логики с имитацией Groq/Supabase прошли. Визуальная проверка браузером в этой среде недоступна; настоящие API-запросы и письма ещё не проверены.

## Подключение устройства и управление

Панель устройства содержит три независимых порога, задержку, длительность импульса, паузу, включение/выключение обратной связи. Кнопки запуска, остановки и калибровки в BLE-режиме отправляют команды на ESP32. Настройки отображаются как подтверждённые только после ответа платы. После потери связи симуляция автоматически не запускается.

Для подключения загрузите **firmware/VerteX_BLE/VerteX_BLE.ino** вместе с соседним **VertexBLEBridge.h**. Это полный скетч на основе присланной рабочей версии. Подробная инструкция — firmware/INTEGRATION.md. Встроенная стартовая калибровка и независимая логика датчиков сохранены; после BLE-отключения моторы и мониторинг останавливаются. Настройки в RAM, до перезагрузки.

Первый тест: Chrome на Windows, Bluetooth включён, сайт открыт по HTTPS → подключить VerteX → прочитать настройки → занять нейтральную позу → калибровать → запустить → проверить три модуля по очереди → изменить параметры и проверить фактическое срабатывание. Поддержка на iPhone через обычный Chrome отсутствует.

Дополнительные программные проверки: BLE-пакеты 20 байт, диапазоны настроек, ответ на команду с правильным ID, отбрасывание дублей и отсчёт времени при 5 пакетах в секунду. Проверка на физическом ESP32 ещё не выполнена.
